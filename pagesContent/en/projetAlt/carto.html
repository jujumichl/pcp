Project Overview

The project was carried out by myself, then Owen joined and helped at the start of his internship. The JS script code is accessible on GitHub: GitHub repository

Origin and Client Need

The project originated from a request by the Town Hall. The council wanted residents to be able to view ongoing and upcoming construction works in the city of Fougères, as well as the impact of those works.

Design Phase

The project already had a first foundation with an existing works mapping, but it was insufficiently documented. I therefore tried to understand how the project worked in order to implement the changes requested by Fabrice. However, the lack of documentation forced me to restart the project from scratch. I researched the various tools involved and thought of a way to make the map stable, which led me to create a database to store the data needed for the mapping.

Development – API Synchronisation Script Database

The database (DB) synchronisation script with the Application Programming Interface (API) was the most substantial part of the work, as we had to manage a connection. Below is the website set up to publish the works map for the city of Fougères.

Project Structure Explained

The project is structured around 5 applications. First, the API retrieves the data. Then, the PostgreSQL/PostGIS database stores the API data, providing stability for the application. GeoServer interprets the data stored in the database, and MapStore displays the data interpreted by GeoServer. Finally, we have our web interface. To keep the database up to date, we created an automatic launch script for the synchronisation process and scheduled it to run automatically.
