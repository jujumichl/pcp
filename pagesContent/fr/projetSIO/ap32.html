Contexte du projet

Pour ce projet, nous avons été répartis en groupes. L’objectif était de réaliser une API REST (Representational State Transfer) Symfony permettant de gérer des stages, des organisations et des contacts. Une API est une interface qui permet à des systèmes logiciels de communiquer entre eux grâce au protocole HTTP. Grâce à cette API, dans notre contexte, nous pouvons créer (POST) et récupérer (GET) un stage et un contact. Nous pouvons aussi modifier et récupérer une organisation grâce à des routes.

Présentation de l'API

Cliquez sur une image pour l’agrandir

Voici à quoi ressemble une API REST : il n'y a pas d'interface graphique et le résultat est présenté en JSON. Le JSON est un format principalement utilisé pour stocker et transporter des données.

Pour plus de simplicité, nous allons passer par une extension Google Chrome qui va nous permettre de faire plus facilement des requêtes spécifiques et de les paramétrer.
Talend, cette extension permet de faire des requêtes HTTP. Nous pouvons ajouter ce que l'on appelle des assertions : elles permettent de faire des vérifications sur le résultat de la requête que nous avons effectuée. Ainsi, nous pouvons effectuer des tests pour vérifier que notre requête renvoie bien ce que nous voulons.

La requête effectuée ci-dessus est une requête GET. Elle nous permet de récupérer tous les stages présents dans notre base de données, construite avec notre ORM (Object Relational Mapper), qui permet de gérer, manipuler et récupérer des tables de données de la même façon qu'un objet, tout en gardant le langage PHP. Nous n'étions que 2 dans le groupe, nous n'avons donc pas pu implémenter l'entrée API pour les contacts.

Requêtes de création (POST)

Voici la requête qui permet de créer un stage. Elle est différente de la récupération d'un stage, où l'on n'avait rien à ajouter : on entrait simplement l'URL et on recevait un résultat. Ici, nous devons ajouter un corps à la requête. Dans ce corps, nous allons ajouter ce qui est requis pour créer un stage (ici, tout le corps que vous voyez en slide 2 est requis). Une fois le corps de la requête écrit, nous n'avons plus qu'à envoyer et nous obtiendrons le résultat en slide 3.

Voici une requête invalide qui essaie de créer un stage. Dans le cas où le corps de la requête est invalide, nous renvoyons une erreur 400 nommée Bad Request. Ainsi, l'utilisateur peut se corriger dans le corps de sa requête.
